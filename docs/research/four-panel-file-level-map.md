# Four-panel file-level decomposition and OmniPanel recomposition

**Reviewed:** 2026-11-04 at the pinned revisions in `four-panel-integration-assessment.md`. **Method:** static inspection of the listed source files and adjacent tests; no installer, service, panel submodule, or production runtime was executed. This is an engineering port map, not a claim that every feature in four broad server products belongs in a least-privilege proxy control plane.

## Recomposition decisions

1. Keep the control plane canonical in PostgreSQL and the node journal narrowly scoped; do not transplant any panel's database schema.
2. Express features as typed data and explicit state transitions. Every externally consequential action needs authorization, bounded inputs, idempotency, an audit record, and observed outcome.
3. Separate observability from enforcement, and presented expiry from canonical expiry. Separate a backup artifact's existence from verified recoverability, including encryption/signing key material.
4. Keep agent operations allowlisted. No shell endpoint, dynamic trusted templates, broad firewall manager, or copied installer is part of this increment.
5. Map source behaviors to independent tests rather than source structures. Exact upstream revisions are recorded in the assessment; this map describes inspected files, not complete coverage of all files/features.

## Increment implemented

`internal/backup/task.go` implements a backup/restore lifecycle contract with queued/running/failed/retry/succeeded and restore-verification states, monotonic timestamps, retry attempt counts, bounded stable error identifiers and required artifact digests for completion. `repository.go` persists records in SQLite WAL with `synchronous=FULL`; it validates absolute paths, private caller-owned parent/database, and WAL/SHM sidecars, and uses serialized, state-checked transitions. Tests cover restart persistence, durability PRAGMAs, hostile filesystem inputs, lifecycle, retries and transition refusal. This remains a local metadata ledger: no PostgreSQL outbox, cross-process lease, artifact provider, encryption/key recovery, scheduler, HTTP surface, or restore executor. It is not evidence of backup/DR readiness.
